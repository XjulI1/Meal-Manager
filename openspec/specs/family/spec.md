## Requirements
### Requirement: Household Creation
The system SHALL allow an authenticated user to create a household if they do not already belong to one.

A household has a name and a unique invite code. The invite code is a 8-character alphanumeric string generated by the system. The creator becomes the first member of the household.

A user belongs to at most one household at any time.

#### Scenario: Create a household
- GIVEN an authenticated user `alice` not belonging to any household
- WHEN she calls `POST /api/households` with `{ name: "Famille Dupont" }`
- THEN a new household is created with name `Famille Dupont`
- AND a unique 8-character invite code is generated
- AND `alice` is registered as a member of this household
- AND the response returns the household details including the invite code

#### Scenario: Already in a household
- GIVEN an authenticated user already belonging to a household
- WHEN she calls `POST /api/households`
- THEN the system returns HTTP 409 Conflict
- AND no new household is created

### Requirement: Joining a Household via Invite Code
The system SHALL allow an authenticated user not belonging to any household to join an existing household using its invite code.

#### Scenario: Join with valid invite code
- GIVEN an authenticated user `bob` not belonging to any household
- AND a household with invite code `ABCD1234`
- WHEN `bob` calls `POST /api/households/join` with `{ inviteCode: "ABCD1234" }`
- THEN `bob` is added as a member of that household
- AND `bob` can access the same inventory, recipes, menus, and shopping lists as other members

#### Scenario: Invalid invite code
- GIVEN an authenticated user not belonging to any household
- WHEN the user submits a join request with an unknown invite code
- THEN the system returns HTTP 404 Not Found
- AND the user is not added to any household

#### Scenario: Already in a household
- GIVEN an authenticated user already belonging to household A
- WHEN the user submits a join request for household B
- THEN the system returns HTTP 409 Conflict
- AND the user remains in household A

### Requirement: Household Membership Isolation
The system MUST scope all household data (inventory, recipes, menus, shopping lists) to the user's household.

A user MUST NEVER be able to read or write data belonging to a household they are not a member of.

#### Scenario: Cross-household access prevention
- GIVEN user `alice` is a member of household A
- AND user `bob` is a member of household B
- AND household A contains an inventory item with id `item-123`
- WHEN `bob` calls `GET /api/inventory/item-123`
- THEN the system returns HTTP 404 Not Found
- AND no information about household A is leaked

### Requirement: Leaving a Household
The system SHALL allow a household member to leave their household.

If the leaving member is the last member, the household and all its associated data (inventory, recipes, menus, shopping lists) MUST be deleted.

#### Scenario: Member leaves a multi-member household
- GIVEN a household with at least two members
- WHEN one member calls `POST /api/households/leave`
- THEN the member is removed from the household
- AND the household and its data remain intact for the other members

#### Scenario: Last member leaves
- GIVEN a household with a single member `alice`
- WHEN `alice` calls `POST /api/households/leave`
- THEN `alice` is removed from the household
- AND the household is deleted
- AND all inventory items, recipes, menus, and shopping lists of that household are deleted

### Requirement: Current Household Retrieval
The system SHALL expose the current authenticated user's household information.

#### Scenario: Authenticated user with a household
- GIVEN an authenticated user belonging to a household named "Famille Dupont"
- WHEN the user calls `GET /api/households/me`
- THEN the system returns the household name, invite code, and list of members (id, email)

#### Scenario: Authenticated user without a household
- GIVEN an authenticated user not belonging to any household
- WHEN the user calls `GET /api/households/me`
- THEN the system returns HTTP 404 Not Found
- AND the client SHOULD redirect the user to the onboarding page
